本章的核心内容主要围绕数据并行计算的基础概念、CUDA C 编程模型的基本结构、线程管理、内存控制以及 CUDA 程序的编译过程展开。以下是第二章的详细内容总结：

### 1. 数据并行性 (Data Parallelism)
*   **基本概念**：**数据并行性**是指对数据集中不同部分执行的计算工作可以彼此独立、并在空间上并行地进行。它是并行程序实现**可扩展性 (Scalability)** 的主要来源。
*   **具体实例**：以“彩色图像转灰度图”为例，每个像素的亮度转换计算完全独立，不依赖于其他像素，这体现了丰富的数据并行性。
*   **与任务并行性 (Task Parallelism) 的区别**：任务并行性通常通过应用程序的**任务分解**来展现（例如，同时执行向量加法和矩阵向量乘法，或者并行执行输入/输出和数据传输）。

### 2. CUDA C 程序结构与异构计算
*   **异构系统架构**：CUDA C 程序运行在包含**主机（Host，即 CPU）**和一个或多个**设备（Device，即 GPU）**的异构系统上。
*   **混合编程与核函数**：单个源文件中可以包含主机代码和设备代码的混合，其中设备代码包含以数据并行方式执行的特殊函数——**核函数（Kernels）**。
*   **执行流程**：程序执行从主机端的串行代码开始。当调用核函数时，会在设备上启动大量的并行线程，这些线程的集合被称为**网格（Grid）**。在所有的线程执行完毕后，网格终止，控制权返回主机继续执行。

### 3. 设备全局内存与数据传输
*   **设备全局内存 (Device Global Memory)**：GPU 拥有其独立的物理内存，即全局内存。主机端代码无法直接解引用设备全局内存指针，必须通过 CUDA API 函数来进行设备全局内存的管理与数据传输。
*   **关键运行时 API**：
    *   **`cudaMalloc()`**：在设备全局内存中分配指定字节大小的空间。与标准 C 的 `malloc()` 返回指针不同，`cudaMalloc()` 将分配的地址写入传入的指针变量中，并利用返回值进行错误检查。
    *   **`cudaFree()`**：释放已分配的设备全局内存空间。
    *   **`cudaMemcpy()`**：在主机和设备内存之间进行数据传输，需要指定源指针、目的指针、传输大小（字节数）以及传输方向（如 `cudaMemcpyHostToDevice` 或 `cudaMemcpyDeviceToHost`）。
*   **运行时开销**：数据分配和传输具有一定的额外开销，因此在实际应用中，通常会将关键数据结构持久保存在设备内存中，通过多次核函数调用来摊销这一开销。

### 4. 核函数与线程管理 (Kernel Functions and Threading)
*   **SPMD 模式**：CUDA 核函数采用**单程序多数据（Single-Program Multiple-Data）**的并行编程模式，即所有线程都执行相同的代码，但处理不同的数据部分。
*   **两级线程组织层级**：线程被组织成两级的阶梯架构：网格（Grid）和线程块（Block）。每个网格包含多个线程块，每个线程块包含多个线程，当前 CUDA 系统中每个线程块最多支持 **1024 个线程**。
*   **内置只读变量**：每个线程可通过内置只读变量获取自身标识并计算其处理的数据范围：
    *   **`threadIdx`**：当前线程在所在的线程块内的局部坐标。
    *   **`blockIdx`**：当前线程块在网格内的块坐标。
    *   **`blockDim`**：线程块的维度大小（例如一维块的线程数）。
*   **全局索引与循环并行化**：在一维组织下，线程可通过公式计算其在网格中的唯一全局索引：**`i = blockIdx.x * blockDim.x + threadIdx.x`**。以此全局索引访问数据，相当于将传统的串行 `for` 循环展开为并行的网格线程（即**循环并行化 Loop Parallelism**）。
*   **自动变量私有性**：核函数内部声明的自动标量变量对每个线程而言都是私有的。
*   **边界条件处理**：由于实际的数据量不一定恰好是块大小的整数倍，因此在核函数中必须使用 **`if (i < n)`** 进行检查，以禁用那些超出数据有效范围的额外线程，避免越界和错误写操作。
*   **限定符关键字**：
    *   **`__global__`**：声明在设备上执行，从主机调用的核函数。
    *   **`__device__`**：声明在设备上执行，只能从设备中调用的函数。
    *   **`__host__`**：声明在主机上执行，只能从主机调用的函数（默认）。

### 5. 调用核函数与执行配置 (Calling Kernel Functions)
*   **启动参数语法**：调用核函数时，通过在函数名和参数之间插入 **`<<<gridDim, blockDim>>>`** 执行配置参数语法来配置启动参数，其中第一个参数指定网格中块的数量，第二个参数指定块中线程的数量。
*   **向上取整（Ceiling Division）计算**：为了使网格中分配的线程总数能够覆盖所有数据元素，通常需要对所需的块数进行向上取整计算，例如 `ceil(n / 256.0)`，或使用整型算术表达式 **`(n + block_size - 1) / block_size`**。

### 6. CUDA C 编译过程
*   **NVCC 编译器**：由于 CUDA 引入了非标准 C 的扩展语法，普通 C 编译器无法直接处理，必须使用 **NVCC（NVIDIA C Compiler）** 编译器进行编译。
*   **代码分离编译**：NVCC 在编译时会将主机代码和设备代码分离：
    *   **主机代码**：纯 ANSI C 代码，由系统自带的标准 C/C++ 编译器进行编译，并作为传统的 CPU 进程运行。
    *   **设备代码**：被编译成 **PTX**（Parallel Thread Execution）虚拟二进制代码，随后由运行时组件进一步编译为能够在特定 GPU 设备上执行的真实机器目标文件（Object Files）并执行。
