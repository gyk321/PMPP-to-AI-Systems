**《Programming Massively Parallel Processors》第五章的主题是“内存架构与数据局部性”（Memory Architecture and Data Locality）**。这一章重点探讨了 GPU 的片上内存架构、如何解决**内存受限型（Memory-bound）**应用的性能瓶颈，并详细讲解了利用**分块（Tiling）**和**共享内存（Shared Memory）**来提高数据复用和带宽利用率的通用方法。

以下是该章节的核心内容总结：

### 1. 内存访问效率与性能瓶颈

- **计算与全局内存访问比（Compute to Global Memory Access Ratio）**：定义为程序中进行的浮点运算次数（FLOP）与从全局内存访问的字节数（B）之比（在文献中也称为算术强度或计算强度）。
- **内存受限瓶颈**：以未优化的矩阵乘法内核为例，每次循环中线程需要从全局内存读取 2 个数据元素（分别来自 \(M\) 和 \(N\) 矩阵），仅执行一次乘法和一次加法。其计算与内存访问比只有极低的 **0.25 FLOP/B**。由于全局内存（离片 DRAM）延迟高（数百时钟周期）且带宽有限，这种低存取比会导致全局内存访问路径迅速发生“交通拥堵”，使大部分计算核心处于闲置等待状态，无法发挥硬件的潜在性能。

### 2. CUDA 内存类型及层次结构

为了优化计算与全局内存访问比，CUDA 提供了多种不同生命周期、作用域和访问速度的设备内存类型，由程序员决定变量在硬件中的驻留位置：

- **全局内存（Global Memory）**：位于芯片外的 DRAM，容量最大但延迟最高（数百时钟周期），对所有线程块可见且可读写。
- **局部内存（Local Memory）**：每个线程私有，物理上同样驻留在片外全局内存中，用于存储无法放进寄存器的数据（如局部数组、溢出的寄存器），延迟与全局内存相同。
- **常量内存（Constant Memory）**：驻留在片外，但通过专用的片上常量缓存（Constant Cache）进行积极缓存，延迟极低。它是只读的且对所有线程可见。
- **寄存器（Registers）**：片上极高速内存，每个线程私有。**核函数中声明的所有自动标量变量（Scalar Automatic Variables）通常都存储在寄存器中**，其访问不消耗全局内存带宽。
- **共享内存（Shared Memory）**：属于片上高速草稿内存（Scratchpad Memory），分配给整个线程块，同一块内的所有线程均可读写该共享内存中的变量，用于实现线程间的高效协同和数据共享，延迟和带宽远优于全局内存。

### 3. 分块技术（Tiling）与局部性（Locality）

- **核心思想**：利用小而快的共享内存来减少大而慢的全局内存流量。它将全局内存中的大数据集划分为较小的子集（称为 **Tiles/分块**），使其能够完全装入共享内存中。
- **数据局部性**：如果算法的计算步骤在某一特定阶段集中访问特定的数据子集，这就构成了数据局部性。
- **减少重复存取**：在矩阵乘法中，不同线程的计算过程存在严重的数据重叠。通过让块内线程协同合作，各自只从全局内存加载一次数据到共享内存分块（`Mds` 和 `Nds`）中，并在片上重复读取（每个元素可被复用 `TILE_WIDTH` 次），能够将全局内存访问量**减少到原来的 \(1/\text{TILE_WIDTH}\)**，大幅度提高算术强度。

### 4. 分块矩阵乘法内核实现与线程同步

分块核函数通过将长的内积循环分解成 `Width / TILE_WIDTH` 个阶段（Phases）来执行。在每个阶段中，通过 **`__syncthreads()`** 障壁同步进行两次关键的步调协调：

1. **加载后的同步**：在线程块的所有线程协同加载当前阶段的分块元素进入共享内存后，调用 `__syncthreads()`，确保所有数据加载完毕，防止任何线程提前读取未加载完成的脏数据。
2. **计算后的同步**：在所有线程完成当前分块的计算后，调用 `__syncthreads()`，确保该阶段所有线程都已用完共享内存中的元素，防止跑得快的线程提早进入下一阶段并覆写仍在被其他线程使用的共享内存（避免读后写/写后读冲突）。

### 5. 边界检查（Boundary Checks）与任意尺寸支持

- 当矩阵的维度不是分块宽度（`TILE_WIDTH`）的整数倍时，边缘的线程可能会试图读取或写入越界的无效数据。
- 核函数必须对**加载 \(M\) 分块、加载 \(N\) 分块、以及写入最终 \(P\) 元素**分别执行不同的边界测试条件。
- 对于越界的内存加载，线程会向共享内存对应位置写入 **`0.0`**。该数值在参与点积的乘加计算时不会改变累加和（\(x + y \times 0.0 = x\)），从而保证了非整除尺寸矩阵在分块计算下的结果准确性。

### 6. 资源占用对硬件占用率（Occupancy）的影响

- **占用率**：指每个 SM 上实际驻留的常驻线程束数量与 SM 支持的最大数量之比。
- 由于 SM 内的共享内存和寄存器资源是固定且被常驻线程块动态瓜分的，如果核函数使用了太多的共享内存或过多的寄存器，会导致 SM 能够同时容纳的常驻线程块数量下降。这会直接拉低占用率，降低 GPU 隐藏指令和内存延迟的能力。
- 为了提高灵活性，可以采用**动态大小共享内存分配**，使主机端代码能在运行时指定共享内存大小，无须为了微调 TILE 大小而重新编译内核代码。
